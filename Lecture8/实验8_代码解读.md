# 实验 8：A* 运动规划代码解读

## 1. 输入与输出

`get_path_from_A_star(start, goal, obstacles)` 接收起点、目标点和障碍物列表。网格点统一使用 `(x, y)` 二元组表示。

函数返回从起点走向目标的路径：

- 每个元素都是二元组；
- 路径包含目标点，但不包含起点；
- 相邻点的曼哈顿距离恒为 1，因此只会水平或竖直移动；
- 目标不可达、目标/起点是障碍物时返回空列表 `[]`；
- 起点等于目标时无需移动，也返回 `[]`。

## 2. A* 的核心思想

A* 为每个候选网格计算：

```text
f(n) = g(n) + h(n)
```

- `g(n)`：从起点到当前网格 `n` 已经走过的步数；
- `h(n)`：从 `n` 到目标的曼哈顿距离；
- `f(n)`：经过 `n` 到达目标的估计总代价。

算法总是优先扩展 `f` 最小的节点。代码使用 `heapq` 实现最小优先队列，使每次取出最佳候选节点的开销为 `O(log V)`。

## 3. 为什么使用曼哈顿距离

四连通网格不允许对角移动，从 `(x1, y1)` 到 `(x2, y2)` 至少需要：

```text
abs(x1 - x2) + abs(y1 - y2)
```

步。障碍物只可能让真实路径更长，不会让它更短。因此曼哈顿距离不会高估剩余代价，是可采纳且一致的启发函数，A* 第一次取出目标节点时得到的就是最短路径。

## 4. 主要数据结构

- `open_heap`：保存等待扩展的节点，优先级为 `(f, h, 插入次序)`；
- `g_score`：记录目前已知的起点到各节点的最小代价；
- `came_from`：记录最短路径中每个节点的父节点；
- `obstacle_set`：把障碍物转换为集合，将碰撞检查从线性查找降为平均 `O(1)`。

## 5. 路径恢复

搜索到目标后，从 `goal` 开始沿 `came_from` 反向回溯，直到 `start`。反向列表中没有加入起点，最后执行 `reverse()`，正好满足“包含目标、不包含起点”的实验要求。

## 6. 搜索边界与不可达情况

题目给的是无限网格，没有明确地图边界。如果目标被障碍物完全包围，直接在无限网格上搜索会一直向外扩展。实现使用“起点、目标和所有障碍物的包围盒，再向外扩一格”作为有限搜索区域。

包围盒外一圈没有障碍物；如果路径需要绕开障碍物，沿这一圈已经可以完成绕行，不需要走得更远。因此该边界不会排除最短路，同时能让不可达情况正常结束。

## 7. 复杂度

若有限搜索区域内有 `V` 个可通行网格、四连通边数为 `E`，则：

- 时间复杂度约为 `O((V + E) log V)`，网格中 `E = O(V)`，可写为 `O(V log V)`；
- 空间复杂度为 `O(V)`，主要用于优先队列、`g_score` 和 `came_from`。

## 8. 运行示例

在当前目录执行：

```bash
python3 test_motion_planning.py
```

示例会打印一条从 `(0, 0)` 到 `(-5, -2)` 的最短无碰撞路径。
