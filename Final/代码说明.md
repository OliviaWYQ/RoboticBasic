# 实验 9 代码说明

提交的主程序是 `turtlebot.py`。程序只依赖 ROS 2 自带的 `rclpy`、
`geometry_msgs` 和 `nav_msgs`，没有使用 NumPy 或 `tf_transformations`，因此在不同
ROS 2 版本的 Linux 电脑上更容易运行。

## 1. 程序结构

程序分为四个部分：

1. **网格地图**：使用 7 个字符一行、共 12 行的 `GRID_MAP` 表示实验地图。
   `#` 是灰色障碍物，`.` 是可以通行的单元格。
2. **A* 路径规划**：`get_path_from_A_star` 使用曼哈顿距离作为启发函数，只扩展
   上、下、左、右四个方向。返回路径包含目标格，但不包含起点格。
3. **三次轨迹生成**：`cubic_coefficients` 为相邻路标点的 x、y 坐标分别生成
   三次多项式，并令每一段的起止速度都为零。
4. **ROS 闭环控制**：`Turtlebot` 节点订阅 `/odom`、发布 `/cmd_vel`，先原地转向，
   再使用“多项式速度前馈 + 位置误差反馈”跟踪每段轨迹。

## 2. 为什么必须经过缓冲格

球位于橙色缓冲格与红色目标格的公共边上。如果直接以红色格为 A* 目标，最短路径
可能从红色格的左边或右边进入，机器人就不会碰到球。因此程序分两次规划：

```text
绿色起点 -> A* -> 橙色缓冲格 -> A* -> 红色目标格
```

这样最后一步一定从橙色格向红色格移动，机器人会从球的下方将球向球门方向推动。

## 3. 坐标系

网格使用 `(列, 行)`：向右列号增加，向下行号增加。ROS 里程计使用普通笛卡尔坐标：
x 向右、y 向上。程序把收到的第一帧 `/odom` 位置视为起始格中心，然后计算其他格子
相对于起始格的位移，所以 Gazebo 世界原点不必与地图原点重合。

`map_yaw` 表示地图向右方向与里程计 x 轴之间的夹角，单位为弧度。默认值为 0；如果
整个环境逆时针旋转 90 度，可将其设为 `1.57079632679`。

## 4. Linux 运行方法

在已启动 TurtleBot Gazebo 仿真的终端中执行：

```bash
source /opt/ros/<你的 ROS 2 版本>/setup.bash
cd <代码所在目录>
python3 turtlebot.py
```

默认起点是右下方绿色格 `(5, 10)`。如果机器人放在其他绿色格，例如 `(3, 9)`：

```bash
python3 turtlebot.py --ros-args -p start_col:=3 -p start_row:=9
```

若 ROS 话题带命名空间，可以使用 ROS 重映射：

```bash
python3 turtlebot.py --ros-args \
  -r /cmd_vel:=/robot/cmd_vel \
  -r /odom:=/robot/odom
```

没有 ROS 时也可以只检查 A* 路径：

```bash
python3 turtlebot.py --plan-only
```

## 5. 常用调节参数

以下参数一般不需要修改。如果机器人打滑严重或在网格中心附近振荡，可在命令行调整：

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `cruise_speed` | 0.16 | 三次多项式的目标峰值速度，单位 m/s |
| `max_linear_speed` | 0.20 | 最大发布线速度，单位 m/s |
| `max_angular_speed` | 1.0 | 最大发布角速度，单位 rad/s |
| `position_gain` | 1.2 | 位置误差反馈增益 |
| `heading_gain` | 2.5 | 航向误差比例增益 |
| `waypoint_tolerance` | 0.055 | 判定到达路标点的距离，单位 m |
| `map_yaw` | 0.0 | 地图相对里程计坐标系的旋转角 |

例如将速度降低到 0.12 m/s：

```bash
python3 turtlebot.py --ros-args -p cruise_speed:=0.12
```

## 6. 轨迹文件

程序正常到达目标或按 Ctrl+C 退出时，会在当前目录生成 `trajectory.csv`。文件每一行
包含实际里程计的 `x,y` 坐标，可以直接交给实验 3 的 `visualization.py` 绘制运动轨迹。
